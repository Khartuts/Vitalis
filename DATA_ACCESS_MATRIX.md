# VITALIS — Data Access Matrix

Sources inspected on **2026-11-20** (official pages fetched during the feasibility phase):

* Samsung Health Data SDK — `developer.samsung.com/health/data/*` (overview, data types, developer mode, app verification, release note **v1.1.0, 2026-03-12**, FAQ, Hello-SDK guides, sleep/steps code labs). The SDK AAR download and the API reference require a Samsung account login and could **not** be inspected.
* Android Health Connect — `developer.android.com/health-and-fitness/health-connect/*`; Jetpack `connect-client` **1.1.0 stable** (1.2.0-alpha06 latest alpha), compileSdk 36, AGP ≥ 8.9.1.
* Google Health API — `developers.google.com/health/*`; production **v4** (`https://health.googleapis.com/v4`), `v4beta` also published. Legacy Fitbit Web API turned off **2026-11-02**. Google Fit APIs supported until end of 2026.
* OpenAI Sign in with ChatGPT / Responses API — `developers.openai.com/siwc/*`, function-calling guide.

## Legend

* **HC** = Health Connect (on-device Android store; Samsung Health can write into it). **SDK** = Samsung Health Data SDK (reads Samsung Health's own store). **GH** = Google Health API v4 (cloud). **EXP** = Samsung Health "Download personal data" export (CSV/ZIP; schema varies by app version).
* **Device column** = "Galaxy Watch6 + Android phone" expectation. ✅ documented & expected · ⚠️ device/region/setting-dependent · ❌ not exposed by any documented interface · 🔍 must be verified on the user's phone with the companion's *Availability probe*.
* **Verification status**: *Docs-verified* = API/type confirmed in official docs; *Code-tested (mock)* = adapter tested against documented shapes; *Device-verified* = confirmed on the user's hardware (none yet — no phone attached to the build environment).

## General access rules

| Interface | Permissions / scopes | History | Incremental sync | Limits |
|---|---|---|---|---|
| HC | Per-type `android.permission.health.READ_*`; `READ_HEALTH_DATA_HISTORY` for >30 days before first grant; `READ_HEALTH_DATA_IN_BACKGROUND` for background reads | Default: 30 days before the first permission grant; unlimited with history permission (Android 14+) | Changes API: per-type `getChangesToken` → `getChanges` (`changes`, `nextChangesToken`, `hasMore`, `changesTokenExpired`); tokens expire if unused for 30 days | Foreground/background periodic + daily quotas (numbers not published); `readRecords` page size default 1000, `pageToken` may be `""` |
| SDK | `Permission.of(DataTypes.X, AccessType.READ)` via `HealthDataStore.requestPermissions`; app must be partner-registered (package + SHA-256) **or** Samsung Health *Developer mode → Developer Mode for Data Read* enabled (testing only) | Not stated in public docs | `readChanges` with `InstantTimeFilter` on change time (UPSERT/DELETE) | Requires Samsung Health ≥ 6.30.2, Android 10+, Java 17; no emulators; errors `ERR_NO_USER_PERMISSION`, `2003` (SDK policy), `PLATFORM_NOT_INSTALLED`, `OLD_VERSION_PLATFORM`, `ERROR_ACCESS_CONTROL` |
| GH | OAuth 2.0; read-only scopes `https://www.googleapis.com/auth/googlehealth.{activity_and_fitness,health_metrics_and_measurements,sleep,profile}.readonly`; Google Cloud project with API enabled; test users while unverified (cap 100); user must first link Google Health in the Google Health mobile app (`users/me/identity`, else 400 `ACCOUNT_NOT_LINKED`) | Account history | `dataPoints.list` with `filter` on start/sample/date/sleep-end time; `pageToken` (default 1440, max 10 000; sleep/exercise max 25); re-query overlapping window + dedupe | Testing-mode refresh tokens expire after 7 days |
| EXP | User-initiated export in Samsung Health app | Full account | Manual | CSV schemas differ across versions → versioned adapters with preview |

## What must be confirmed on the user's phone

The companion includes an **Availability probe** (Settings → *Check what my phone shares*) that, after permissions are granted, reads the last 30 days per type and reports: record count, data-origin packages (e.g. `com.sec.android.app.shealth`), device type, newest timestamp. The desktop's *Data Sources* screen renders this report. Until that report exists, every 🔍 entry above is shown in the app as "unknown — not yet verified on your device".
